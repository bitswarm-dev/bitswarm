## Bitswarm 1.0.0

Bitswarm 1.0.0 is the first release that treats hooks as a full automation tool. A hook can now call an API, run a script or run `curl` when something happens, with keys kept out of the database. It is also the first release with a hardened security baseline and a router that keeps your view in the URL.

### Highlights

- **Run curl as a hook.** A third hook type starts the real `curl` program with a command you write, such as `curl -sf -X POST https://example.org/hook -d {{torrent.name}}`. The editor starts with a template. It follows the same rules as command hooks, plus curl-specific safety checks: placeholders are single-quoted, it needs `SWARM_ALLOW_COMMANDS=1`, and the Docker image now includes curl.
- **Paste curl to fill an API hook.** Paste a command from an API's docs or "Copy as cURL" in your browser, and the editor fills in the method, URL, headers and body. It only reads the text. It never runs curl or sends a request.
- **Keep API keys out of the database.** Write `{{secret.NAME}}` in an API hook and set `SWARM_SECRET_NAME` (or `SWARM_SECRET_NAME_FILE` for Docker secrets) on the server. The value is never saved, shown or logged. Keys typed into headers such as `Authorization` are masked after you save.
- **Security: every `npm audit` finding fixed**, including an open-redirect XSS in the router the dashboard shipped. `react-router` is gone, replaced by TanStack Router, so nothing from the vulnerable family remains.
- **Shareable views.** The torrent list filters, search, sort, selected torrent and inspector tab, the settings section and the Execution log filters now live in the URL. Links work, back and forward work, and routes load their data before they show and split into small chunks.
- **Speed chart window.** Settings → Speed sets how much history the sidebar chart shows, from 30 seconds to an hour, without using more memory.

### Dashboard router migration

The dashboard moved from `react-router` 6 to TanStack Router, in [#9](https://github.com/bitswarm-dev/bitswarm/pull/9). The old router could only be fixed by a major upgrade that broke navigation, so it was removed rather than patched.

- **File-based routes.** One file per page under `src/routes/`, with a generated and committed route tree. Each route's page loads as its own chunk, so the first load is smaller.
- **Data before the page.** Each route has a loader that prefetches its queries, so a page doesn't fetch twice or flash empty. A skeleton appears only after 200 ms, and routes share one error and not-found screen.
- **Typed links.** Navigation uses typed `<Link>` and `useNavigate`, never hand-written paths. Sidebar entries are real links: hover preloading, middle-click and open in a new tab work.
- **Your view is in the URL.** The torrent list's status and tag filters, search, sort, selected torrent and inspector tab, the settings section (`/settings/<section>`) and the Execution log filters are URL parameters. You can bookmark or share them. Back and forward work, and junk in the URL is ignored. Typing in a search box doesn't flood the history.
- **No redirect target from the URL.** The new router takes none, which closes the open-redirect XSS. It makes no API calls while you're signed out.
- **Server data stays in TanStack Query.** React Context now holds only UI state: theme, toasts, sidebar collapse and row selection.

### Security

- Curl hooks can't be tricked by a torrent name. A curl hook only saves if every placeholder follows a name and an equals sign, such as `name={{torrent.name}}`, or is `{{payload}}`. `-F` and `--form` are refused, values starting with `-`, `@` or `<` get a leading space, and a saved hook that breaks the rule isn't run. Without this, a torrent named `x@/etc/passwd` could make curl read a file and send it to the hook's server.
- The database folder is created `0700` and the file `0600`, and an existing file is tightened at startup.
- Query strings such as `?apikey=...` are removed from hook, schedule and update-feed errors, so they never reach the log or a stored delivery.
- Secret references are resolved only where the hook author wrote them, and error messages never print a secret.
- Stored header keys are masked in the editor and the API. `********` means "keep the saved key".
- Dependency updates: golang 1.27, alpine 3.24, nginx 1.31 and node 26 base images, Vite 6 and the matching React plugin, and the npm audit fixes.

### Fixes

- A command hook that timed out on Linux left its command running. Each hook now runs in its own process group, and the whole group is stopped on timeout.
- The Execution log re-rendered in a loop while it was open.

### Also new

- Pull requests and pushes to `main` run CI for the server and the dashboard.
- The README leads with automation and hooks, with screenshots and an email example.
- Releases are cut manually from a tag on `main`, and the tag is the only source of the version.
- The third-party notices list the new dependencies and licenses.
- The hook editor no longer lists `SWARM_TORRENT_LABEL`, which was removed with labels.

### Upgrading

- **Docker:** `docker compose pull && docker compose up -d`. The server image now includes `curl`.
- **Your data is kept.** Existing hooks, presets, schedules and settings load as before. Saved keys in headers keep working. Move them to `{{secret.NAME}}` when you can.
- **Curl and command hooks** still need `SWARM_ALLOW_COMMANDS=1`. Imported hooks start turned off.
- **Backups:** leave "include secrets" off when you export one.

### Known gaps

These are unchanged and are shown in the app: per-torrent speed limits, sequential download, tracker status, and applying port, DHT and encryption changes without a restart. See the README for the full list.
