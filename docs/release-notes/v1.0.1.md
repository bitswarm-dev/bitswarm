## BitSwarm 1.0.1

A small release after 1.0.0: one feature is removed, and the docs gain recipes with screenshots. There are no database or settings changes.

### Removed

- **Paste curl** in the hook editor, and `POST /api/hooks/parse-curl` ([#15](https://github.com/bitswarm-dev/bitswarm/pull/15)). It sat next to **Run curl** and looked like the same feature, but it only filled in an API hook. Hooks you already created with it are ordinary API hooks and keep working. To use a curl command from a service's docs, enter its method, URL, headers and body in **Call an API**, or use **Run curl**.

### Docs

- **Hook recipes** ([`docs/hook-recipes.md`](https://github.com/bitswarm-dev/bitswarm/blob/main/docs/hook-recipes.md)): copy-paste **Call an API** hooks that keep their keys out of the database with `{{secret.NAME}}`, for Cloudflare Email, Resend, Discord, Slack, Telegram, ntfy, Pushover and Gotify, plus a signed call to your own server. Each one lists the `SWARM_SECRET_...` variables to set. All of them were created through the hooks API to check they save, but none was sent to the real service.
- **Scheduled download recipes** ([`docs/schedule-recipes.md`](https://github.com/bitswarm-dev/bitswarm/blob/main/docs/schedule-recipes.md)): a distribution download page (Debian netinst) and Ubuntu Server, both run against the live pages, a search with a list of terms, a single results page, and a rename preset that sorts files into folders.
- Screenshots of the hook editor (command and curl), the Cloudflare hook, the Debian schedule with its live preview, and the rename preset.
- The Run curl editor's help text now explains where placeholders may go: right after an equals sign, or inside a URL or a `-H` value.

### Upgrading

- **Docker:** `docker compose pull && docker compose up -d`.
- **Nothing to migrate.** Hooks, schedules, presets and settings load as before.
- If you used the **Paste curl** tab, nothing breaks. Anything you saved from it stays an API hook.
